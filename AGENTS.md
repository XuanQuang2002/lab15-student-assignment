# Agent Guidelines

This is a learning project for education and a CV/portfolio. Keep the work easy for the learner to understand, explain, and maintain.

## Ask permission first

- Before editing files, running commands, installing dependencies, or taking other actions, explain what you intend to do and ask for permission.
- Wait for explicit approval. Silence is not approval.
- Approval covers only the agreed work. Ask again before expanding the scope.
- If the user has explicitly requested the exact action, that request counts as permission for that action.

## Keep the code simple

- Write the smallest clear solution that meets the assignment requirements.
- Use descriptive names, straightforward functions, and readable control flow.
- Follow the existing project structure and tools.
- Avoid unnecessary code, dependencies, abstractions, classes, configuration, and unrelated refactoring.
- Add validation and error handling only where there is a concrete need.
- Prefer readable code over clever shortcuts or premature optimization.

## Support learning

- Explain what changed and why in plain language.
- Use short comments to explain non-obvious decisions, without repeating the code.
- Work in small, understandable steps so the learner can explain the solution in an interview.
- Preserve the assignment's learning goals and required technologies.
- Suggest a small, relevant check; run it only with permission and report the actual result.
